Public block explorers are firehoses: 8 figures of USDT shuffles every minute,
most of it CEX internals. **You can't watch one wallet by hand, and copy-pasting
an address into Etherscan every hour isn't a strategy.**

whale-watch-tg inverts the workflow: subscribe to an address once, and every
transfer that touches it arrives in Telegram as a human sentence — enriched
with exchange tags and a buy/sell-pressure read, rate-limited so the channel
stays readable.

> ⚠️ **Informational only — not trading advice.** On-chain heuristics (exchange
> inflow ≈ sell pressure) are priors, not guarantees. See [Caveats](#-caveats).

---

## What it does

- 📡 **Cursor-safe watcher** — polls public Ethereum RPCs for ERC-20 `Transfer`
  events, persists a scan cursor in SQLite, and dedupes on `(tx_hash, log_index)`.
  Crashes never skip blocks, re-scans never duplicate alerts.
- 🏷️ **Exchange enrichment** — a bundled known-address list (Binance, Coinbase,
  Kraken, OKX, Bybit, …) tags every sender/receiver and classifies the move:
  *to exchange → likely sell pressure*, *from exchange → likely accumulation*,
  *same-entity → internal rebalancing noise*.
- 🧠 **LLM summaries, template fallback** — plug any OpenAI-compatible endpoint
  (`WHALE_WATCH_LLM_URL` + key) for free-form narratives; zero config still gets
  you deterministic, well-formed summaries — an alert is never lost to a model
  outage.
- 🤖 **Telegram bot** — `/subscribe 0x…`, `/unsubscribe`, `/list`, `/status`;
  per-user command cooldown plus per-chat alert caps (10/h default, 5 s min gap).
- 🧪 **Zero-key demo** — `whale-watch demo` renders 8 bundled fixture transfers
  through the *real* pipeline into terminal alerts + a self-contained
  [HTML preview](examples/whale-alert-preview.html). No network, no keys, ≤ 3 min.

| Layer | Choice |

## Quickstart

```bash
whale-watch demo            # zero keys: terminal alerts + web preview
```

## Live mode

```bash
# Watch Binance's hot wallet from the console (public RPC, zero keys)
whale-watch watch --subscribe 0x28c6c06298d514db089934071355e5743bf21d60

# Deliver alerts to real Telegram chats (needs a bot token)
TELEGRAM_BOT_TOKEN=12345:ABC… whale-watch watch --send-telegram

# The bot itself (subscription CRUD)
TELEGRAM_BOT_TOKEN=12345:ABC… whale-watch bot
```

Bot commands: `/start` · `/subscribe <address> [TOKEN]` · `/unsubscribe <address>`
· `/list` · `/status` · `/help`.

| Env var | Purpose |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Bot token from [@BotFather](https://t.me/BotFather) — required for `bot`/`--send-telegram` |
| `WHALE_WATCH_LLM_URL` | OpenAI-compatible base URL (e.g. `https://api.openai.com/v1`, OpenRouter, Ollama) |
| `WHALE_WATCH_LLM_API_KEY` | Key for the above |
| `WHALE_WATCH_LLM_MODEL` | Model name (default `gpt-4o-mini`) |

Tracking native ETH moves needs a trace-capable RPC (Alchemy/Infura); the public
RPC path tracks ERC-20s (USDT, USDC, WBTC, LINK, … see `whale_watch/data/tokens.json`).
Fixtures/demo cover ETH natively via synthetic transfers.

## How it works

```text
public RPC ──> eth_getLogs(Transfer topic, cursor+1..cursor+N) ──> decode (decimals-aware)
                                                                        │
                                        subscriptions (SQLite) ──> match sender/receiver
                                                                        │
                     enrich (exchange tags, direction) → summarize (LLM | template)
                                                                        │
              rate limit (10/h · 5 s gap) → Telegram / console / preview page
```

Idempotence is structural: events dedupe on a `(tx_hash, log_index)` primary
key, and the cursor advances only after each batch is persisted.

## Caveats

- **Not trading advice.** Inflow-to-exchange *correlates* with sell pressure;
  it is not a signal that guarantees price action. Same-entity rebalancing is
  tagged `internal` precisely because it isn't.
- The bundled exchange address list is community-maintained, best-effort
  public data (wallets rotate over time). Tags are hints, not facts.
- Public RPCs cap `eth_getLogs` ranges — the scanner batches (default 2,000
  blocks) and halves the batch on rejection.
- Events arrive after block finality; there is no mempool tracking. Large
  private-relay trades never hit the public mempool anyway — on-chain capture
  is the complete view, just a few seconds later.
- Demo fixture transfers are synthetic (fake tx hashes) for illustration only.
